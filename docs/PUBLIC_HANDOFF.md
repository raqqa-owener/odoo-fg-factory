# Public Handoff

## 現在地

本プロジェクトは、ERP仕様書をOdoo向けの構造化設計へ変換し、追加開発支援へ応用できるかを検証したPoCです。

別プロジェクトを優先したため、以下の到達点で開発を停止しています。

## 実装・検証済み

- 構造化Packの取込
- Odoo標準置換候補の正規化
- Fit & Gapの分離
- ノード／リレーションの参照整合性検証
- Neo4j dry-run／apply
- 顧客確認用Question Pack
- 回答済みPackの再取込
- 内部設計Packの取込・検証
- Odooアドオン生成用データへの接続
- 非破壊的なOdooデモアドオンの生成検証

## 未完成

- ERP資料を直接検索するRAG基盤
- 追加開発要求から影響範囲を推定するエージェント
- ベンダー向け最終仕様書の全自動生成
- 本番レベルの認証・権限・監査
- Dynamics 365からOdooへの全面移行

## 重要な設計判断

1. LLMによる意味解釈と、コードによる検証・適用を分離する。
2. 未確認のFit & Gapを推測で自動実装しない。
3. Neo4j書込み前にdry-runと参照整合性を検証する。
4. 顧客向け情報と内部設計情報を分離する。
5. Odoo標準モデルを破壊せず、追加実装はオーバーレイを優先する。

## 公開版への移行方針

公開版はallowlist方式で作成し、必要なファイルだけを採用します。

除外対象:

- 元企業・顧客の資料
- 会社名、個人名、組織、権限、承認経路データ
- 実行履歴、バックアップ、生成ZIP
- 顧客回答Pack
- 認証情報、シークレット
- 配布不可の評価版ライブラリとライセンス

## 再開する場合の次工程

1. 完全な架空データによる代表シナリオを固定する。
2. 追加開発要求を入力する影響分析APIを設計する。
3. Graph上の関連モデル、項目、画面、権限を探索する。
4. 根拠付きの影響範囲レポートを生成する。
5. 顧客確認資料とベンダー向け実装資料を生成する。
